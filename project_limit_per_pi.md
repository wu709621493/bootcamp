# Project Limit per PI

## Purpose
Set a clear cap on the number of active projects led by each Principal Investigator (PI) to improve execution quality, mentoring bandwidth, and resource allocation.

## Policy (recommended baseline)
- **Active-project cap:** Maximum **3 active projects per PI** at any given time.
- **New-project gate:** A PI at cap may open a new project only after closing or transferring one active project.
- **Co-PI handling:**
  - A project counts toward the cap for the **lead PI**.
  - Co-PI participation does not count toward cap unless designated as co-lead.
- **Exception path:** Time-limited exceptions can be approved by the program committee for critical deliverables.

## Definitions
- **Active project:** Funded or formally approved work with ongoing milestones, allocated people, and open deliverables.
- **Closed project:** Final report accepted and no open budget/personnel commitments.
- **Transferred project:** Lead responsibility reassigned and documented.

## Intake and review workflow
1. **Proposal submitted** with PI load snapshot.
2. **Capacity check** against active-project cap.
3. If at cap, proposal moves to:
   - deferred queue, or
   - exception review.
4. **Quarterly portfolio review** validates project status (active/paused/closed).

## KPI dashboard
Track the policy with lightweight operational metrics:
- Average active projects per PI.
- Percentage of PIs at/above cap.
- On-time milestone completion rate.
- Student/postdoc supervision satisfaction.
- Budget variance per project.

## Implementation notes
- Start with a **6-month pilot** before permanent adoption.
- Publish a transparent exception log.
- Revisit cap annually by discipline (e.g., computational vs. wet-lab throughput differences).

## Example governance language
> Each Principal Investigator may serve as lead on up to three active projects simultaneously. Requests exceeding this limit require committee-approved exceptions with explicit duration and risk mitigation.
