# Pseudoshima

Pseudoshima is an imagined "island of prototypes" where ideas are treated like living ecosystems rather than finished products.

## Core idea

A project enters Pseudoshima when it is:

- **Concrete enough to test** (it has a draft form people can interact with), and
- **Flexible enough to evolve** (it is expected to change based on feedback).

## Three principles

1. **Prototype before polish**  
   Build the smallest useful version first.
2. **Feedback as fuel**  
   Every critique is considered design data.
3. **Iteration in public**  
   Progress is documented so others can learn from the path, not just the outcome.

## Why it matters

Pseudoshima encourages teams to move faster without pretending the first version is final. It creates a culture where experimentation is normal, failure is informative, and improvement is continuous.
